- App/editor/shared source must not import from `three/src`.
- Node-material constructors must come from `three/webgpu`, not deep Three internals.

- Runtime render helpers and node-material primitives can load without renderer setup.

## Current Migration Shape

The migration work is not a package bump right now. It is cleanup around local compatibility code:

- Keep `three/webgpu` as the source for node material constructors exposed to behavior scripts.
- Keep `three/tsl` as the TSL surface exposed through both `THREE.TSL` and the top-level `TSL` alias for script API compatibility.
- Keep unsupported legacy loader wrappers only as API-compatible stubs until import/export surfaces no longer reference those formats.
- Prefer `three/addons/...` wrappers over copied or package-manager-loaded loader implementations.
